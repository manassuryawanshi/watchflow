Privacy Policy

Effective Date: October 6, 2026 • WatchFlow v1.0.0

WatchFlow is designed with a fundamental commitment to privacy, data sovereignty, and user autonomy. Unlike algorithmic web services, WatchFlow is built on a local-first execution model. We do not operate remote user tracking servers, do not maintain central user profiles, and do not monetize browsing data.

1. Local Storage Architecture

All information created, managed, or computed by WatchFlow is stored strictly on your local device via Google Chrome's standard chrome.storage.local API. WatchFlow does not transmit this data to external databases or cloud synchronization endpoints.

Storage Key Type Purpose
yt_focus_settings Object Stores your user preferences (e.g., Focus Mode on/off, daily time limits, Cooldown duration, course mode banner toggles).
yt_focus_learning_queue Array Stores your saved videos and course playlists, lecture titles, lesson completion checkboxes, and course duration metrics.
yt_focus_daily_stats Object Stores daily viewing second tallies (total watch time, focused study time, learning queue time) aggregated by local date.
yt_focus_recent_sessions Array Stores a rolling local record of recent study sessions (video title, channel, duration, timestamp) displayed on the Analytics dashboard.
yt_focus_schedules Array Stores user-defined time windows for scheduled Focus Mode or YouTube blocking.
yt_focus_cooldown_state Object Stores temporary cooldown break state when hard daily limits are reached.

2. Zero Telemetry & Network Calls

WatchFlow performs zero network requests to any remote backend server, tracking service, or telemetry collector. Specifically:

  • No analytics SDKs (Google Analytics, Mixpanel, Segment, PostHog, or Sentry) are included in the codebase.
  • No tracking pixels, third-party cookies, or fingerprinting scripts are executed.
  • The extension does not query YouTube Data API servers and requires no API key. All DOM transformations and playlist parsing happen locally in your browser.

3. Permissions Justification

WatchFlow strictly complies with the Google Chrome Web Store Least Privilege policy:

  • storage: Required to read and write your user settings, Learning Queue, and local study analytics in chrome.storage.local.
  • activeTab: Allows the extension toolbar popup to detect if you are currently on a YouTube video page to enable the "Add to Queue" action and report active video metadata.
  • *://*.youtube.com/*: Host permission required to inject content scripts (youtube.js and youtube.css) into YouTube pages to suppress feeds, render WatchFlow Today, enforce Focus Mode allowlists, and inject the Window Fullscreen player button.

WatchFlow requests no broad permissions such as <all_urls>, webRequest, cookies, history, or identity.

4. Data Portability & Complete Erasure

You retain complete ownership over your data at all times:

  • Export to JSON: From the WatchFlow Dashboard (Settings → Data Management), you can export your entire Learning Queue and study analytics history as a clean, human-readable JSON file.
  • One-Click Wipe: You can clear your watch history, empty your Learning Queue, or permanently erase all stored keys and restore factory defaults at any time. When you uninstall the extension, Chrome automatically deletes all local storage associated with WatchFlow.

5. Open Source Transparency

The complete source code of WatchFlow is open source and available for public audit on GitHub at https://github.com/manassuryawanshi/watchflow. Any developer can verify that the runtime code adheres strictly to these declarations.

6. Policy Updates

If future releases introduce optional cloud backup or synchronization features, those capabilities will be strictly opt-in and will require explicit user consent before any data leaves your local device.
